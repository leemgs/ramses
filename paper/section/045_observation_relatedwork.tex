\subsection{Positioning of RAMSES}
\label{sec:positioning}

Table~\ref{tab:related_positioning} lays out the structural differences
between RAMSES and a set of representative systems along five axes:
tier scope, NUMA awareness, the formality of regime modeling,
evaluation duration (Eval.~Dur.), and energy reporting (throughput-per-watt,
TP/W). ``Part.'' marks partial support; ``Arch.'' marks
architectural-level analysis only.
The general picture is that prior LLM-serving frameworks tune for
throughput or stretch memory via partial GPU--CPU coordination---but
none of them evaluates the same combination of intra-node NUMA placement, resource preallocation, and pressure-driven policy switching.

Several recent TII papers address complementary layers without touching
the intra-node memory dynamics RAMSES targets: digital-twin latency
modeling~\cite{tao2019digitaltwin}, cloud--edge resource
coordination~\cite{cao2021edgecps}, DRL-based mobile-edge
allocation~\cite{chen2021drl,deng2020edgerl}, accuracy--latency model
splitting~\cite{wu2021dnninference}, and communication-efficient federated
digital twins~\cite{lu2021dtfl} coordinate at the network, task, or device
level, while hierarchical fog scheduling~\cite{chekired2018fogscheduling}
treats inference nodes as latency constants. All treat the node as an
opaque, fixed-latency unit. RAMSES sits one layer below, characterizing
regime-dependent VRAM--DRAM--NVMe behavior inside a single serving node and
producing the empirical latency distributions those schedulers assume.

\subsection{Distinct Contributions of RAMSES}
What is distinctive is the combination of hierarchical VRAM--DRAM--NVMe
orchestration with an analytical regime characterization built on a latency
decomposition over compute, locality, transfer, and synchronization. Observable
pressure ratios classify capacity and transfer stress; the three modules---GPU
Process Allocator (context conflicts), Task Memory Manager (NUMA-aware
allocation), and GPU Booster (swap-aware asynchronous control)---play distinct
roles but are judged against the same regime boundaries, with the focus on
single-node QoS and sustained-load behavior under a parameterized synthetic
workload.
